# Job Market Category Predictor API

A FastAPI service that predicts a job's category (data analyst, data scientist, data engineer, etc.) from its title and description, using a model trained on real job market data from the job-market-tracker and job-market-sql projects. Fourth and final project in a portfolio pipeline series.

## What it does

- Trains a TF-IDF + Logistic Regression classifier on job listing text (train_model.py)
- Serves the trained model through a FastAPI app with a /predict endpoint (main.py)
- Given a job title and optional description, returns a predicted category
- Includes interactive API documentation (auto-generated by FastAPI) at /docs

## Tech stack

Python, scikit-learn, pandas, joblib, FastAPI, uvicorn

## Setup

1. Clone this repo and create a virtual environment:
   python3 -m venv venv
   source venv/bin/activate
   pip install -r requirements.txt

2. (Optional) Retrain the model from the included database:
   python train_model.py

3. Run the API:
   uvicorn main:app --reload

4. Open http://127.0.0.1:8000/docs to test the /predict endpoint interactively

## Example request

POST /predict
{
  "title": "Senior Data Engineer",
  "snippet": "Looking for someone with Python and SQL experience"
}

Response:
{
  "predicted_category": "data engineer"
}

## How the model works

- Job title and description text is converted into numerical features using TF-IDF (Term Frequency-Inverse Document Frequency)
- A Logistic Regression classifier learns the relationship between those features and category labels
- This replaces the rule-based keyword matching used in earlier projects (job-market-sql, job-market-dashboard) with a model that learns patterns from the data itself

## Limitations

- **Class imbalance.** With only one example each of "data scientist" and "machine learning engineer" in the training set (compared to 12 for "data engineer"), the model struggles to learn these minority categories and seems to default to the majority class. This is an expected result given the small dataset size and documented here rather than hidden. A larger, more balanced dataset (which can be achieved by running the collection script over more time) would likely improve this.
- With only ~27 rows total, there isn't enough data for a proper train/test split, so the model is trained on the full dataset rather than validated on held-out data. This is a proof-of-concept model, not a production-grade classifier.
- The model only sees text it was trained on — categories or job titles very different from the training examples may be misclassified.

## Possible next steps

- Collect more training data over time to address class imbalance
- Add a proper train/test split and evaluation metrics once more data is available
- Deploy the API publicly (Render/Railway) for live testing
- Connect this API to the dashboard project, so predictions can be tried interactively in the UI
